# On-Device Assistant

A chat assistant that answers questions about Mayank Rai's portfolio entirely on the device, with no server and no API key. It runs Gemma 4 E2B through [`flutter_edge_ai`](https://flutteredge.ai/docs/getting-started) and LiteRT-LM. This feature is a showcase of on-device AI, so it is opt-in, feature-flagged and disabled on web.

## Features

- Opt-in from Settings, with a consent sheet that states the download size.
- One-time model download (about 2.4 GB) from Hugging Face, with progress, cancel and delete.
- Chat screen with suggestion chips, scroll-to-bottom and a loading indicator.
- Answers only from the portfolio data. Unrelated questions are politely refused.
- Deterministic answers for contact details and computed career facts, so numbers are never generated by the model.
- Retrieval of the most relevant facts per question, plus a one-line digest of every record.
- Works offline once the model is downloaded.
- Supported on Android, iOS and macOS. Not offered on web (`isAssistantSupported`).

## Getting Started

### Enabling the feature

The assistant is hidden unless all of these are true:

1. The platform is native (`isAssistantSupported` in `assistant_availability.dart`).
2. The feature flag `feature_ai_assistant` is on. Its default is `false`; see [Configuration](#configuration).
3. The user has enabled it in Settings. The preference is stored in `AssistantEnabledCache`.
4. The model is downloaded.

The floating `AssistantButton` (portfolio screen) and the Settings card only show their active state once the bloc reports `AssistantReady`.

### Module configuration

`AssistantModuleConfigurator` (`@generateConfigurator`) is listed in `module_configurators.dart`. Its `postDependenciesSetup`:

- registers `AssistantFeatureFlags.all` with `AppFeatureFlagDefinitionRegistry`;
- on supported platforms registers `AssistantModuleRoute.assistant` (`/assistant`) and dispatches `AssistantInitializedEvent` to the singleton `AssistantBloc`.

After changing annotated classes, regenerate the DI code:

```bash
dart run build_runner build --delete-conflicting-outputs
```

## Architecture

```text
assistant/
  assistant.dart                       public barrel
  assistant_availability.dart          isAssistantSupported (not web)
  assistant_module_configurator.dart   DI, flags, route, init
  data/
    cache/assistant_enabled_cache.dart           opt-in preference
    repository/flutter_edge_ai_assistant_repository.dart   model + prompt + inference
    repository/assistant_context_selector.dart             fact retrieval and budgeting
    repository/assistant_direct_answerer.dart              deterministic answers
  domain/
    feature_flag/assistant_feature_flags.dart
    repository/assistant_repository.dart
    use_case/                          one use case per action (see below)
  presentation/
    route/, widget/assistant_button.dart
    screen/assistant/                  bloc, state, events, tracking, content widget
```

Layering follows the app conventions: widgets dispatch bloc events, the bloc calls use cases, use cases call `AssistantRepository`. Only the repository knows about `flutter_edge_ai`.

### Use cases

| Use case | Purpose |
|----------|---------|
| `GetAssistantContextUseCase` | Loads the portfolio and builds the JSON context (overview lines, digest, records). |
| `AskPortfolioQuestionUseCase` | Answers a question for a given context. |
| `PrepareAssistantModelUseCase` | Downloads and readies the model, reporting progress. |
| `CancelAssistantPreparationUseCase` | Cancels a running download and deletes partial files. |
| `DeleteAssistantModelUseCase` | Unloads the model and deletes its files. |
| `IsAssistantModelDownloadedUseCase` | Checks if the model file is on the device. |
| `GetAssistantEnabledUseCase` / `UpdateAssistantEnabledUseCase` | Reads and writes the opt-in preference. |

All failures map to `UnknownAssistantFailure`. Use cases are logged by `LogUseCaseInterceptor`, so they do not log themselves.

### Bloc and state

`AssistantBloc` is a registered singleton shared by the portfolio screen, Settings and the chat screen. Its state holds a sealed `AssistantStatus`, so impossible combinations (such as "ready while downloading") cannot exist:

| Status | Meaning |
|--------|---------|
| `AssistantUnavailable` | The feature flag is off. |
| `AssistantOff` | Available, but the user has not enabled it. |
| `AssistantDownloading(progress)` | Downloading or loading, 0 to 100. |
| `AssistantReady` | Enabled with the model downloaded. |
| `AssistantFailed` | Enabled, but the download or load failed. |

Events: `AssistantStartedEvent` (screen opened, loads the context), `AssistantInitializedEvent` (startup and screen resume, idempotent), `EnableAssistantClickEvent`, `DisableAssistantClickEvent(deleteModel)` and `SendAssistantQuestionClickEvent`.

The initialisation event is dispatched again whenever a screen becomes visible, so a flag toggled at runtime from the dev menu is picked up. Setup itself runs once (`_hasInitialized`).

## How It Works

### Model lifecycle

- **Model:** `litert-community/gemma-4-E2B-it-litert-lm`, file `gemma-4-E2B-it.litertlm`, pinned to a commit revision. The repository is public, so no Hugging Face token is needed. A gated model such as Gemma 3 would need `huggingFaceToken` passed to `FlutterEdgeAi.initialize`.
- **Download:** `FlutterEdgeAi.installModel(...).fromHuggingFace(...)` with progress and a `CancelToken`.
- **Lazy load:** if the model is already installed, the bloc reports `AssistantReady` at startup without loading it. The engine is created on the first question (`answer()` calls `prepareModel`). Loading takes about 7 s on a mid-range phone with the GPU backend, so the first answer is slower.
- **Readiness probe:** on load the repository runs a 16-token generation. The assistant is only usable after a real generation succeeds.
- **Backend:** `PreferredBackend.gpu`, `maxTokens: 8192`.
- **Unload:** disabling in Settings unloads the model. "Delete" also removes the file.

### Answering a question

`FlutterEdgeAiAssistantRepository.answer` handles one question at a time:

1. **Direct answer.** `AssistantDirectAnswerer` tries to answer from the computed data. If it matches, the model is never called (see below).
2. **Follow-up detection.** The previous question is passed only if the new one looks like a follow-up (contains words such as "else", "also", "there", or starts with "and", "in", "for"). A standalone question must not see the previous one, because the small model tends to answer that instead.
3. **Context selection.** `AssistantContextSelector` builds the facts for the prompt, within a byte budget.
4. **Generation.** A fresh chat is created per question with a system instruction (portfolio-only rules), `topK: 40`, `maxOutputTokens: 512` and `temperature: 0.2`. The facts sit in the user turn next to the question, where the small model attends to them better than in a long system prompt. There is no conversation memory.
5. **Degeneration guard.** If the answer contains a run of 12 or more of the same character, the question is retried once with temperature 0.7 and a smaller context. If it still fails, the user sees the normal error.

Debug builds log each question and answer as `[Assistant] Q:` / `A:`.

### The portfolio context

`GetAssistantContextUseCase` serialises the whole portfolio into one JSON document with these sections:

| Section | Content |
|---------|---------|
| `asOf` | Today's date. |
| `overview` | Pre-computed lines (below). |
| `digest` | One short line per record: profile, every role, every project, skill group and service. |
| `profile`, `experiences`, `projects`, `expertises`, `services`, `testimonials` | Full records. |

The overview exists because a 2B model cannot rank, count or add dates reliably, so these are computed in Dart and stated outright:

- Career overview (role and company counts), shortest, longest, first and current role.
- Total time per country and per city, with overlapping roles counted once.
- Roles by work mode (remote, freelance).
- Time per technology across all roles (overlap counted once).
- Career gaps and job changes, leadership roles.
- Education and spoken languages, stated outright so country names are not mistaken for languages.
- Two long lists ("All roles in chronological order" and "All roles from shortest to longest"), included only for career-style questions.

### Context selection

The raw JSON is far larger than the 8192-token window, so `AssistantContextSelector` flattens it into small facts and keeps the best ones within `maxContextBytes` (10 000):

- A fact scores higher when its words match the question. A record whose company, title or name is mentioned scores 100, each matching word adds 10, and summaries add 50.
- Short overview lines are always offered. Long lists need career-style terms (years, countries, cities, education, comparisons and so on).
- The digest lines come after matching facts, so every record is still visible.
- Question terms are expanded (for example "study" becomes education, institution, degree).
- The previous question contributes only a small score.
- Facts are added in score order until the budget is full. A fact that does not fit is skipped.
- The budget is also capped by what fits the token window after the system instruction and the question (about 2 bytes per token, with 1024 tokens reserved for the answer).

### Deterministic answers

The 2B model sometimes garbles digits ("2 years and 111 months") or collapses into repeated characters, so questions with computed answers skip it. `AssistantDirectAnswerer` returns the overview line as written for:

- email, phone and "how can I contact";
- how long in a given city or country;
- how many years with a given technology;
- longest and shortest role, first and current role, career gaps and job changes, leadership, number of companies or roles, and spoken languages.

Questions that name a place or company together with a comparison ("longest job at X") still go to the model.

## Configuration

| Setting | Where | Default |
|---------|-------|---------|
| Feature flag `feature_ai_assistant` | `AssistantFeatureFlags.aiAssistant` (Firebase Remote Config, with a local override in dev tools) | `false` |
| Opt-in preference | `AssistantEnabledCache` (`assistant_enabled_cache`) | off |
| Model repository and revision | constants in `flutter_edge_ai_assistant_repository.dart` | Gemma 4 E2B, pinned commit |
| `_maxTokens`, `maxOutputTokens`, `maxContextBytes` | repository and selector | 8192, 512, 10 000 |

Strings live in `lib/l10n/arb/app_{en,es,nl}.arb` under the `assistant*` keys.

## Tracking

The chat screen reports through `AssistantTrackingDelegate`, injected into the bloc. Widgets and the bloc never call the event tracker directly.

## Data Quality

Answers are only as good as the portfolio data. Missing or placeholder fields are listed in [`DATA_GAPS.md`](DATA_GAPS.md), together with what each fix would unlock.

## Limitations

- A 2B model can still misread facts. Anything computable should be added to the overview and the direct answerer rather than prompt rules.
- Answers take about 3 to 6 s once loaded (prefill 2 to 4 s, then about 25 tokens per second). The first question also pays the 7 s model load.
- Each question starts a fresh conversation, so there is no memory beyond the follow-up hint.
- The model file is about 2.4 GB and needs a device with enough memory for the GPU backend.
- Hot restart can leave the native engine alive. Stop and rerun the app instead.

## Testing

```bash
cd app/portrai
flutter test test/src/feature/assistant test/src/feature/setting
dart analyze --fatal-infos .
```

- `assistant_golden_questions_test.dart` asserts which facts are selected for many real phrasings over a synthetic portfolio. Add a case here whenever a question phrasing fails.
- `assistant_direct_answerer_test.dart` covers the deterministic answers.
- `assistant_context_selector_test.dart` and `get_assistant_context_use_case_test.dart` cover selection and the context builder.
- `assistant_bloc_test.dart` covers the status transitions, including the lazy load.
- The model itself is not exercised in tests; the repository takes an injectable loader.
